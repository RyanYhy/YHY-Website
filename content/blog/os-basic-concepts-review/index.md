今天把程序、作业、进程，以及并发、并行、同步和异步这几个概念重新整理了一遍。一开始我能记住它们大概的定义，但放在一起的时候，还是不太清楚各自到底在描述什么。

第二遍学习后，我觉得先问清楚一个问题会更容易理解：**这个概念是为了说明什么事情？** 下面就按这个思路，把这几个概念的区别记下来。

## 程序、作业与进程 {#program-job-process}

这几个概念放在一起时，我最想分清的是：程序描述的处理方法、交给系统的工作要求，以及实际执行这项工作的过程，分别对应什么。

### 程序记录处理方法 {#program}

准确来讲，程序是为了完成某些任务而组织的指令和相关数据。它记录的是一套处理方法，描述计算机应该怎么做。

比如有一段图片缩放代码，规定了怎么读取图片、计算新的尺寸、输出结果。即使还没有运行，这段程序也已经存在了。

因此，理解程序时，我先抓住它描述的处理方法。存放在磁盘还是加载进内存，是另一个层面的问题。

### 作业描述完整的工作要求 {#job}

作业一开始是我认为最难理解的概念。后来把它放到具体例子里，我才觉得清楚了一些。

假设我现在要缩放两张图片，除了有图片缩放程序，还需要告诉系统：处理哪两张图片、缩放比例是多少、结果保存在哪里。如果有多个处理步骤，还要说明这些步骤的要求和顺序。

在操作系统教材的批处理语境里，可以把这样提交给系统的一项完整工作理解为作业。它包括所需的程序、数据和有关的控制说明。

也就是说，**程序关注怎么做，作业关注要让系统完成什么工作。**

这里面需注意，现实中说的“任务”范围很大，不能直接把所有任务都等同于操作系统里的作业。我先用“完整的工作要求”帮助理解，再结合教材里的具体语境去判断。

### 进程描述一次执行实例 {#process}

进程是程序的一次执行实例及其运行环境。系统需要记录执行到了哪里、使用哪些资源、当前处于什么状态，才能组织这次执行。

还是图片缩放的例子：

- 图片缩放的代码和相关数据，描述的是程序。
- 输入图片、缩放比例、输出位置和处理要求，构成这次提交的作业。
- 为完成这项工作而创建的运行实例，就是进程。

这些概念也不是严格的一一对应。同一程序可以被运行多次，形成不同进程；一项作业也可能分成多步，由多个进程共同完成。

这里面需注意，进程存在，不代表它此刻一定在 CPU 上执行。理解进程时，还需要看它当前处于什么状态。

在三态模型里，进程有就绪态、运行态和阻塞态：就绪是已经具备运行条件，等待分配 CPU；运行是正在执行；阻塞则是在等某个事件，比如 I/O 完成。五态模型再加上新建态和终止态。

这样再看，进程的“动态”描述的是一次有状态变化的执行过程。

### 线程与执行调度 {#thread}

一个进程可以包含一个或多个线程。在常见的现代操作系统模型中，进程通常是资源分配和保护的基本单位，线程是 CPU 调度的基本单位。[Microsoft 的进程与线程文档](https://learn.microsoft.com/en-us/windows/win32/procthread/processes-and-threads)也将线程描述为操作系统分配处理器时间的基本单位。

我把它们理解为：进程组织资源，线程承载具体的执行流程。同一进程里的线程通常共享进程的地址空间等资源，但可以有各自的执行进度。

**小结复盘**：

1. 程序记录处理方法，作业描述提交给系统的完整工作，进程是执行实例。
2. 程序和进程不等同，进程存在也不意味着一直占用 CPU。
3. 区分进程和线程时，需分清资源分配与执行调度这两件事。

## 并发与并行 {#concurrency-parallelism}

把程序怎么运行理清后，接下来的问题就是：如果有多个任务，它们是怎么一起推进的？

并发和并行本身是更抽象的概念。在操作系统中，我可以用多个进程或线程的执行来理解它们，但这两个概念的适用范围不止于此。

### 并发关注共同推进 {#concurrency}

**并发是多个任务在同一段时间内共同推进，不要求在同一时刻执行。**

先考虑只有一个逻辑处理器的简化情况，任务 A 和任务 B 可以交替执行：

```text
时间向右推进
执行顺序：A → B → A → B → A → B
```

虽然每一时刻只执行其中一个任务，但把观察范围放到这一段时间，两个任务都取得了进展，这就是并发。

所以“交替执行”是并发的一种实现方式。换到有多个执行资源的环境，任务也可以同时推进。

### 并行关注同时执行 {#parallelism}

**并行是多个任务在同一时刻同时执行。**

比如两个逻辑处理器各自执行一个任务：

```text
同一时间段
逻辑处理器 1：A A A A
逻辑处理器 2：B B B B
```

在上面这个例子里，A 和 B 既在同一段时间内共同推进，也确实同时执行，因此同时体现了并发和并行。

[Go 官方对并发与并行的说明](https://go.dev/blog/waza-talk)区分了它们关注的问题：并发涉及如何组织多个独立推进的活动，并行涉及计算是否同时执行。我先抓住这两个问题，再去判断具体例子。

讨论普通软件线程时，**只有一个逻辑处理器，多个线程就需要交替执行；有多个逻辑处理器时，多个线程可以同时执行。** 这里的逻辑处理器，可以先理解为操作系统能够分别安排线程执行的处理单元，它不一定与物理核心一一对应。本节只讨论软件线程的执行。

**小结复盘**：

1. 并发看多个任务能否在一段时间内共同推进，并行看它们是否同时执行。
2. 并发可以通过交替执行实现，也可以利用多个执行资源。
3. 判断时先说明讨论的是任务、线程还是硬件，避免一句“CPU 同时只能做一件事”概括所有情况。

## 调用中的同步与异步 {#sync-async}

并发和并行是在讨论多个任务如何推进。同步和异步在这里关注的是另一个问题：**发起一个操作后，调用方要不要等它完成，才能继续后续流程？**

我先用下面两句话建立印象：

- 同步调用：等操作完成、返回后，再继续当前调用流程。
- 异步调用：发起操作后可以先继续，结果稍后再通过约定的方式获得。

以一个耗时请求为例，同步调用可以这样理解：

```text
我发起操作 A → 等 A 完成并返回 → 我再继续
```

异步调用则可以这样理解：

```text
我发起操作 A → 我先继续其他工作
A 完成后     → 通过回调、事件等方式处理结果
```

这里“不等结果”不是说结果不重要，也不是永远不用等。后续真正依赖结果时，仍然需要协调处理。[MDN 的异步编程介绍](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Async_JS/Introducing)用的也是发起耗时操作、继续响应其他事件、完成后接收结果这个思路。

### 同步调用的执行顺序 {#synchronization}

我觉得“同步”这个词容易让人先想到“同时进行”，但在同步调用里，需要关注的是调用方接下来能不能继续执行。

还是以图片缩放为例。假设我调用一个同步的缩放函数，那么这次调用完成并返回后，当前流程才能执行下一步。就算下一步是与缩放结果无关的其他工作，也需要等这次调用返回。

如果用的是异步缩放接口，发起操作后，当前流程可以先去做不依赖结果的事情。等图片缩放完成，再通过回调、事件等约定方式取得结果并保存。

所以我先这样理解：**同步调用把当前流程的继续执行，放在这次调用完成之后；异步调用允许当前流程先继续，稍后再处理结果。** 两种方式里，真正使用缩放结果，都必须等结果准备好。

### 异步与并行的区别 {#async-vs-parallel}

异步并不保证两个任务同时在 CPU 上执行。比如单线程事件循环可以在请求发出后处理其他事件，等结果到达时再处理回调；这些回调仍然可能在同一个线程上依次执行。

反过来，即使底层用了多个线程并行计算，调用方也可能一直等到结果返回。因此，不能看到“异步”就直接理解成“开了另一个线程”，也不能拿能否被打断来判断同步和异步。

**小结复盘**：

1. 同步与异步在这里看调用流程与操作完成之间的关系，并发与并行看多个任务如何推进。
2. 异步结果通常稍后再处理，不代表不用处理，也不保证并行。
3. 异步允许先做不依赖结果的事情；真正使用结果时，仍然必须等结果准备好。

## 今天的复盘 {#review}

这次重新整理后，我觉得最需要记住的是：定义里用到的词看起来接近，但它们关注的问题不一样。

程序、作业、进程这一组，我先问处理方法是什么、要完成什么工作、系统怎样组织执行。并发、并行这一组，我先分清共同推进和同时执行。到了同步、异步，再看发起操作以后，当前调用流程与结果之间是什么关系。

先把问题分开，再回头看定义，比单独记“静态”“动态”“交替”“等待”这些词更容易理解一些。
